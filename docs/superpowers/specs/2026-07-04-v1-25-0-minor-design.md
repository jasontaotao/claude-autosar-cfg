## Motivation

v1.23.0 MINOR shipped the DBC→Com-Stack bridge that auto-generates ECUC value-side skeletons (Com/CanIf/PduR containers) from a DBC file. Real OEM flow today: customers paste the auto-generated ARXML, then **manually edit** 50-500 instances to fix naming conventions, ECU partition tags, PduR routing — all hand-typing into the ARXML by opening it in this editor. Each mis-typed `<SHORT-NAME>` or wrong container path is a round-trip through BSWMD validation.

v1.25.0 MINOR closes that pain. Customers paste their hand-edited Excel from their existing Excel-based ECU workflow, click once, and get a serialized `ecuc-value-set` ARXML that satisfies the project's BSWMD. The Excel file is the OEM's existing artifact format — they already have one, we don't have to teach them a new one.

**Constraint still applies** (per v1.24.0 brainstorming): one-way write only. No ARXML→Excel reverse path.

User-confirmed scope during brainstorming (all "你选"):

1. **Range**: Com-stack only (Com / CanIf / PduR modules). NOT generic any-container.
2. **Input format**: `.xlsx` only (SheetJS). NOT `.csv` (deferred PATCH).
3. **Template generator**: yes, wizard downloads BSWMD-derived template with pre-filled headers.

## Goals

1. **Batch create Com-stack value-side instances from a single `.xlsx`** — 5 instance kinds: `ComIPdu`, `ComSignal`, `CanIfTxPdu`, `CanIfRxPdu`, `PduRRoutingPath`. Multi-sheet (one sheet per kind).
2. **Provide a BSWMD-derived template** — wizard offers downloadable `.xlsx` whose headers are read from the project's BSWMD definitions, so OEMs don't mis-name columns.
3. **Per-row collision control** — preview shows red-flagged rows where the shortName already exists; per-row toggle (`overwrite` / `skip`) before commit (different from DBC idempotent dedup).
4. **3-file atomic write** — same 2-phase commit + snapshot rollback pattern as `dbcImportComStackHandler`.

## Non-Goals (explicit YAGNI)

- **No `.csv` support** — deferred to v1.25.x PATCH if confirmed demand.
- **No Dem / Dcm / Dcm DID / DTC batch** — independent MINOR (v1.26.0 path already listed in v1.24.1 release notes).
- **No generic any-container batch** — Excel is wired to Com-stack's 5 kinds only; UX simpler.
- **No batch delete** — out of scope.
- **No cross-project template sharing** — each project's BSWMD is different; template is generated per-project.
- **No Excel formula evaluation** — sheets are pure values; evaluated cells produce strings only (SheetJS default `cellFormula:false`).
- **No streaming for huge sheets** — 5MB hard cap; OEM Excel workflows rarely exceed 5k rows.
- **No reverse direction (ARXML → Excel)** — out of scope per v1.24.0 constraint.

## Architecture (one paragraph)

main process gets a 3-IPC cluster (`template` / `parse` / `import`) modeled on `dbcImportComStackHandler`. `xlsxToEcucBatch` mapper is a pure function under `src/core/bridge/` (no IO), invoked from the import handler. `applyPatchSteps` is reused for in-memory mutations; the import handler adds the 2-phase atomic write + snapshot rollback coordination for the 3 ECUC files (Com.arxml / CanIf.arxml / PduR.arxml). UI is `XlsxBatchWizard`, a 3-step React wizard cloning the proven `DbcImportWizard` shape. Dynamic `await import('xlsx')` keeps SheetJS out of the main-process startup bundle.

```
User .xlsx
   ↓ parseXlsxSheetRows  (T1 new — pure: Uint8Array → EcucInstanceRow[][] per sheet)
   ↓ xlsxToEcucBatch      (T2 new — pure: EcucInstanceRow[] + moduleDef → PatchStep[])
   ↓ applyPatchSteps      (existing v1.18+: per-file in-memory mutation)
   ↓ parseArxml / serializeArxml / writeAtomic (existing v1.18+)
   ↓ 3-file 2-phase write + snapshot rollback (DBC pattern)
```

## Data model

### Sheet → instance kind mapping

| Sheet 名          | ECUC 容器                             | 父容器路径                               | 出现于      |
| ----------------- | ------------------------------------- | ---------------------------------------- | ----------- |
| `ComIPdu`         | `<ECUC-CONTAINER-VALUE>` of `ComIPdu` | `Com/ComConfig/ComIpdu`                  | Com.arxml   |
| `ComSignal`       | `ComSignal`                           | `Com/ComConfig/ComSignal`                | Com.arxml   |
| `CanIfTxPdu`      | `CanIfTxPdu`                          | `CanIf/CanIfConfig/CanIfTxPdu`           | CanIf.arxml |
| `CanIfRxPdu`      | `CanIfRxPdu`                          | `CanIf/CanIfConfig/CanIfRxPdu`           | CanIf.arxml |
| `PduRRoutingPath` | `PduRRoutingPath`                     | `PduR/PduRRoutingTables/PduRRoutingPath` | PduR.arxml  |

Unrecognized sheet name → `parse-failed` error with offending sheet name in message.

### Sheet row schema (5 cols + N param cols)

```
shortName,definitionRef,param:<PARAM_NAME_1>,param:<PARAM_NAME_2>,...
```

- `shortName` (required) — becomes `<SHORT-NAME>` of the new container.
- `definitionRef` (optional) — overrides default BSWMD `DEFINITION-REF DEST=...` per-row; allows rows targeting a custom sub-def.
- `param:<NAME>` (optional columns) — each maps to a `set-param` step. Values are `string | number | boolean | null` per existing `PatchStep.set-param` schema.
- Empty columns → skip the param (don't emit `set-param` step).
- 1st row in the sheet is header (read once per import).

### `EcucInstanceRow`

```ts
export interface EcucInstanceRow {
  readonly sheet: 'ComIPdu' | 'ComSignal' | 'CanIfTxPdu' | 'CanIfRxPdu' | 'PduRRoutingPath';
  readonly shortName: string;
  readonly definitionRef?: string;
  readonly params: Readonly<Record<string, string | number | boolean | null>>;
}
```

`xlsxEcucBatchParseHandler` returns `EcucInstanceRow[]` plus per-row `collidesWithTarget: boolean` (derived from existing-tree walk).

### `PatchStep[]` shape emitted by `xlsxToEcucBatch`

```ts
// Per instance:
{
  op: ('add-child', parentPath, shortName, definitionRef);
} // ONE container
// + zero-or-more:
{
  op: ('set-param', containerPath, paramName, value);
} // per param col
```

Helper functions: `buildComIPduStep(row, parentPath)`, `buildComSignalStep`, `buildCanIfTxPduStep`, `buildCanIfRxPduStep`, `buildPduRRoutingPathStep`. Each emits the `add-child` first then loops over `row.params` keys for `set-param`.

## IPC contract

```ts
// src/shared/types.ts — 3 new request/response types + 1 instance shape

export interface EcucInstanceRow {
  readonly sheet: 'ComIPdu' | 'ComSignal' | 'CanIfTxPdu' | 'CanIfRxPdu' | 'PduRRoutingPath';
  readonly shortName: string;
  readonly definitionRef?: string;
  readonly params: Readonly<Record<string, string | number | boolean | null>>;
}

// IPC #1: xlsx:parseBatch
export interface XlsxParseBatchRequest {
  readonly projectManifestPath: string;
  readonly xlsxBytes: Uint8Array;
}
export type XlsxParseBatchResponse =
  | {
      readonly ok: true;
      readonly value: {
        readonly instances: readonly EcucInstanceRow[];
        readonly collisions: Readonly<Record<string, boolean>>; // key = "<sheet>:<shortName>"
      };
    }
  | {
      readonly ok: false;
      readonly error: {
        readonly kind: 'read-failed' | 'parse-failed' | 'no-module-def';
        readonly message: string;
      };
    };

// IPC #2: xlsx:writeBatchTemplate
export interface XlsxWriteBatchTemplateRequest {
  readonly projectManifestPath: string;
}
export type XlsxWriteBatchTemplateResponse =
  | { readonly ok: true; readonly value: { readonly xlsxBytes: Uint8Array } }
  | {
      readonly ok: false;
      readonly error: { readonly kind: 'read-failed' | 'parse-failed'; readonly message: string };
    };

// IPC #3: xlsx:commitBatch
export interface XlsxCommitBatchRequest {
  readonly projectManifestPath: string;
  readonly instances: readonly EcucInstanceRow[];
  /** Per-collision-row decision. Key format: `<sheet>:<shortName>` (matches
   *  the collision map keys returned by `xlsx:parseBatch`). Rows whose key
   *  is absent default to `skip`. */
  readonly resolutions: Readonly<Record<string, 'overwrite' | 'skip'>>;
}
export type XlsxCommitBatchResponse =
  | {
      readonly ok: true;
      readonly value: {
        readonly added: number;
        readonly overwritten: number;
        readonly skipped: number;
        readonly perFile: Readonly<Record<'Com' | 'CanIf' | 'PduR', number>>;
      };
    }
  | {
      readonly ok: false;
      readonly error: {
        readonly kind: 'read-failed' | 'parse-failed' | 'bridge-failed' | 'write-failed';
        readonly message: string;
      };
    };
```

Pattern follows v1.23.0 DBC handler: `{ ok: true, value } | { ok: false, error: { kind, message } }` envelope, NOT discriminated union (per v1.24.0 spec correction note).

## Error handling

- `read-failed` — `.xlsx` > 5MB / corrupt Zip / project file missing / BSWMD parse failed.
- `parse-failed` — sheet name not in the 5 allowed kinds / unrecognized column header / missing required `shortName`.
- `bridge-failed` — `add-child` step apply failed (BSWMD path mismatch); rare.
- `write-failed` — 3-file atomic write failed entirely; snapshot rollback triggers, project restored to pre-state.
- `no-module-def` — at least one of the 3 ECUC files (Com/CanIf/PduR) has no `<DEFINITION-REF>` or its BSWMD module-def is missing.
- `collision-detected` — NOT an error; surfaced as `collisions` map in parse response; per-row decision captured in commit request's `resolutions` map. Default = `skip` (safest).

Renderer display: error.kind maps to a fully-translated i18n key (no English fallback strings — v1.23.0 T3.1 + v1.23.1 T1 lesson).

## UI flow (`XlsxBatchWizard`, 3-step)

**Step 1 — TemplateDownload**:

- Big button: "Download starter template".
- Below: collapsible help text listing the 5 valid sheet names with 1-line descriptions.

**Step 2 — UploadAndPreview**:

- File input (`.xlsx` only).
- After parse, render a table per sheet with rows.
- Collision rows get red background + a per-row radio: `skip` / `overwrite` (defaults to `skip`).
- Total instance count + collision count summary.
- "Back" + "Next: Commit" buttons.

**Step 3 — Commit**:

- Disabled until user picks resolutions for all collision rows.
- Click "Commit" → spinning → IPC #3 (`xlsx:commitBatch`).
- Success: dialog showing `Added: N · Overwritten: N · Skipped: N · Files modified: Com, CanIf, PduR`.
- Error: dialog showing the i18n-translated message.

i18n keys (6 × 2 = 12 entries):

- `xlsxBatch.wizard.title`
- `xlsxBatch.wizard.step1.download`
- `xlsxBatch.wizard.step2.upload`
- `xlsxBatch.wizard.step3.commit`
- `xlsxBatch.error.{kind}` × 5 kinds (read/parse/bridge/write/no-module)
- `xlsxBatch.success.summary`

## Risks

1. **SheetJS bundle size in main process**: `xlsx` minified is ~470KB. **Mitigation**: dynamic `await import('xlsx')` inside IPC handlers (NOT at module load), so startup overhead stays at 0. Verified in v1.23.0 mutator handler precedent.
2. **BSWMD field count explosion**: a `ComIPdu` can have 30+ PARAM-CNF definitions. **Mitigation**: the template's 1st row is a single-line comment column header (e.g., `,param:ComHandleId,param:ComIPduDirection,...`); if a Com-stack kind has > 20 columns the template generator emits a 2nd-row hint text.
3. **Collision UX complexity**: the 2-stage preview+commit with per-row toggle is new flow. **Mitigation**: T2 unit-test case #2 pins the contract explicitly; e2e test verifies full round-trip.
4. **3-file atomic write without independent test in main**: snapshot rollback was tested via DBC handler, but Excel adds 2 new handler-level surfaces. **Mitigation**: T2 unit-test case #3 simulates a write failure (lock one of the 3 files read-only on Windows via chmod).
5. **BSWMD cache invalidation after Template generation**: if the project's BSWMD changes after the user downloads a template, headers become stale. **Mitigation**: the wizard always re-runs TemplateDownload → re-parses → re-emits, every time; no cache.
6. **i18n bypass regression**: per v1.23.1 T1 L1 + v1.24.0 T3.1 L1 lessons. **Mitigation**: T4 test verifies each error surface is i18n-keyed (no hardcoded English), all 12 keys present in both locale clusters.
