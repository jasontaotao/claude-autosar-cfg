# v1.26.0 MINOR — Xlsx Mapper BSWMD-Driven Refactor Design Spec

> **Design date:** 2026-07-05
> **Status:** DRAFT (awaiting user review)
> **Goal:** Eliminate the hardcoded BSWMD-side path strings in `src/core/bridge/xlsxToEcucBatch.ts` by deriving paths from BSWMD via the existing `lookupContainerDef` infrastructure at call time. The mapper becomes BSWMD-aware; sheet-name → parent-path mapping is read from the canonical BSWMD, not baked into source.

## Background

### The brittleness problem

The v1.25.x PATCH cycle (shipped at `5634023`) and v1.25.2 PATCH (shipped at `49ef5d9`) both closed regressions caused by the bridge mapper (`src/core/bridge/xlsxToEcucBatch.ts`) hardcoding BSWMD-side path strings. The mapper's `SHEET_TO_PARENT_PATH` const declares:

```ts
const SHEET_TO_PARENT_PATH = {
  ComIPdu: 'Com/ComConfig/ComIpdu',
  ComSignal: 'Com/ComConfig/ComSignal',
  CanIfTxPdu: 'CanIf/CanIfConfig/CanIfTxPdu',
  CanIfRxPdu: 'CanIf/CanIfConfig/CanIfRxPdu',
  PduRRoutingPath: 'PduR/PduRRoutingPaths/PduRRoutingPath',
} as const;
```

The v1.25.1 PATCH T3 enrichment (commit `006840d`) renamed the demo-ecu PduR BSWMD's container from canonical `PduRRoutingPaths` to non-canonical `PduRRoutingTables`. The mapper's hardcoded `Paths` value silently misaligned with the BSWMD's `Tables` value, causing every `PduRRoutingPath` `add-child` step to be soft-filtered by the engine's `path-not-found` advisory filter. End users saw no error but the PduR instance was never created in the committed ARXML. v1.25.2 PATCH restored the BSWMD to its canonical name; this spec eliminates the brittleness that allowed the drift to occur.

### Why hardcoded paths are fundamentally brittle

The mapper's hardcoded `parentPath` strings name BSWMD-defined container shortNames that the mapper never validates against an actual BSWMD. If the BSWMD evolves (different parent container, different shortName casing, different nesting depth), the mapper silently fails because its hardcoded value no longer matches reality. The engine's `path-not-found` advisory filter masks the failure — no error is surfaced to the user.

The repository already has the machinery to eliminate this brittleness:

- `src/core/project/bswmd.ts:458` exports `lookupContainerDef(BswModuleDef, shortName): ContainerDef | null`, which walks the BSWMD module's container list (including sub-containers) and returns the canonical `ContainerDef` with its `.path` field. Used by tests at `bswmd.test.ts:1023`.
- `src/main/ipc/xlsxEcucBatchImportHandler.ts` already parses the demo-ecu BSWMDs from `samples/arxml/demo-ecu/bswmd/` at handler invocation time.
- The `add-child` PatchStep already accepts an optional `definitionRef: string` field (line 48 of xlsxToEcucBatch.ts and the mutation engine already stamps `definitionRef: childContainerDef.path` at `src/core/arxml/mutation.ts:175`).

What is missing is **the connection**: the xlsx mapper looks up the container via a hardcoded string instead of via `lookupContainerDef`.

## Goal

Refactor `xlsxToEcucBatch` to accept a `bswmds: ReadonlyMap<string, BswModuleDef>` parameter (keyed by module shortName) and a minimal `SHEET_TO_MODULE` const (sheet-name → module shortName). For each row, the mapper:

1. Looks up `SHEET_TO_MODULE[row.sheet]` to determine the module shortName.
2. Fetches `bswmds.get(moduleShortName)` to get the BswModuleDef.
3. Calls `lookupContainerDef(mod, row.sheet)` to get the `ContainerDef`.
4. Uses `containerDef.path` as the `parentPath` on the emitted `add-child` PatchStep.

After the refactor, no BSWMD-side path string is hardcoded; the only hardcoded constant is the sheet-name → module-shortName mapping (1 level of indirection, not a path string).

## Non-Goals

- **Dcm services generator** (5 UDS kinds) — deferred to v1.27.0 MINOR per v1.25.2 release notes Out of Scope section.
- **dbcToComStack.ts refactor** — already mostly value-walk from v1.23.0 T2 (see comments at lines 11–19 of `dbcToComStack.ts`). Minor path-construction cleanup is a separate concern, deferred.
- **odxToDiagnosticExtract.ts refactor** — different schema concern (ODX diagnostic extract, not AUTOSAR ARXML ECUC mutation). Out of scope.
- **Adding new sheet kinds** (Dem, ComM, EcuC, etc.) — requires both BSWMD data + xlsx schema work; separate scope.
- **Generic BSWMD-driven mapping for non-xlsx bridges** — dbc mapper's value-walk approach stays as-is; doc-gen ODX stays as-is.
- **Backward-compatible wrapper** — the `xlsxToEcucBatch(rows)` signature is internal to main-process code; the single caller (`xlsxEcucBatchImportHandler.ts`) is updated in the same MINOR.

## Architecture

### Replacement: `SHEET_TO_MODULE` (1-level hardcoded, no paths)

Replace the 5-entry path-bearing `SHEET_TO_PARENT_PATH` const with a 5-entry module-bearing `SHEET_TO_MODULE` const:

```ts
const SHEET_TO_MODULE = {
  ComIPdu: 'Com',
  ComSignal: 'Com',
  CanIfTxPdu: 'CanIf',
  CanIfRxPdu: 'CanIf',
  PduRRoutingPath: 'PduR',
} as const;
```

Only module shortNames remain hardcoded; no path fragments. The mapper does not encode "ComIPdu → ComConfig → ComIpdu" — it asks `lookupContainerDef` what the actual path is.

### New signature

```ts
export function xlsxToEcucBatch(
  rows: readonly EcucInstanceRow[],
  bswmds: ReadonlyMap<string, BswModuleDef>,
): PatchStep[];
```

`ReadonlyMap` (not `Map`) to signal no internal mutation; callers pass a frozen map (or just any `ReadonlyMap`). Tests use a fixture built from the demo BSWMDs or a synthetic BswModuleDef.

### Lookup loop (per row)

```ts
for (const row of rows) {
  if (!row.shortName || row.shortName.length === 0) {
    throw new Error(`EcucInstanceRow missing shortName (sheet=${row.sheet})`);
  }
  const moduleShortName = SHEET_TO_MODULE[row.sheet as keyof typeof SHEET_TO_MODULE];
  if (moduleShortName === undefined) {
    throw new Error(
      `Unrecognized sheet name: '${row.sheet}' (allowed: ${Object.keys(SHEET_TO_MODULE).join(', ')})`,
    );
  }
  const bswmd = bswmds.get(moduleShortName);
  if (bswmd === undefined) {
    throw new Error(
      `BSWMD map missing module '${moduleShortName}' (needed by sheet '${row.sheet}'). ` +
        `Provided modules: ${Array.from(bswmds.keys()).join(', ') || '<empty>'}`,
    );
  }
  const containerDef = lookupContainerDef(bswmd, row.sheet);
  if (containerDef === null) {
    throw new Error(
      `Container '${row.sheet}' not found in BSWMD module '${moduleShortName}'. ` +
        `Verify the BSWMD declares this container shortName.`,
    );
  }
  const parentPath = containerDef.path;
  const containerPath = `${parentPath}/${row.shortName}`;
  // ... emit add-child + set-param steps as before
}
```

The per-row line count grows from ~3 lines to ~10 lines, but the loop body is now data-driven instead of string-driven.

### `xlsxEcucBatchImportHandler.ts` update

The handler currently invokes `xlsxToEcucBatch(instances)`. After this MINOR, it parses the per-module demo BSWMDs and passes them:

```ts
// At the start of the handler invocation (after IPC payload validation):
const demoBswmds = await parseDemoBswmds(projectManifestPath); // new helper
const res = xlsxToEcucBatch(instances, demoBswmds);
```

`parseDemoBswmds` is a new helper that resolves `samples/arxml/demo-ecu/bswmd/Bsw_<Module>_Bswmd.arxml` filenames to parsed `BswModuleDef` objects and returns a `ReadonlyMap<string, BswModuleDef>`. It lives in `src/core/bridge/demoBswmdLoader.ts` (new file, ~40 LOC) so it can be unit-tested independently from the IPC handler.

### Caller compatibility

Only one production caller: `src/main/ipc/xlsxEcucBatchImportHandler.ts`. Both files updated in the same MINOR. No external API surface change (the IPC contract is `xlsxEcucBatchImportHandler(IpcPayload): IpcResult` and stays unchanged).

## Data Flow

```
.xlsxz EcucInstanceRow{sheet:'PduRRoutingPath', shortName:'NewRoute', params:{}}  ────┐
                                                                                       │
                                                                                       ▼
                                                                       ┌────────────────────────────────────┐
                                                                       │ xlsxEcucBatchImportHandler          │
                                                                       │   1. parseDemoBswmds(manifestPath)  │
                                                                       │      → ReadonlyMap<string,          │
                                                                       │         BswModuleDef>               │
                                                                       │   2. xlsxToEcucBatch(rows, bswmds)  │
                                                                       └─────────────────┬──────────────────┘
                                                                                         │
                                                                                         ▼
                                                                       ┌────────────────────────────────────┐
                                                                       │ xlsxToEcucBatch per row:           │
                                                                       │   sheet → moduleShortName           │
                                                                       │   bswmds.get(moduleShortName)       │
                                                                       │   lookupContainerDef(mod, sheet)    │
                                                                       │   → ContainerDef.path = parentPath  │
                                                                       └─────────────────┬──────────────────┘
                                                                                         │
                                                                                         ▼
                                                                       PatchStep[] { add-child, set-param* }
                                                                       forwarded to applyPatchSteps (engine)
```

The engine's `applyPatchSteps` consumes the `PatchStep[]` exactly as before; no engine changes are required. The mapper's emission format is identical except `parentPath` now reflects the BSWMD's actual canonical path rather than a hardcoded string.

## Error Handling

Three error classes surface at mapper construction time (before any patch is emitted), distinct from engine-side errors:

| Error                  | Trigger                                         | Error message shape                                                                                    | Test                                                                       |
| ---------------------- | ----------------------------------------------- | ------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------- |
| Unknown sheet          | `sheet` value not in `SHEET_TO_MODULE`          | `Unrecognized sheet name: '<X>' (allowed: ...)`                                                        | `xlsxToEcucBatch-bswmds.test.ts: unknown sheet throws with allowed list`   |
| Missing module         | `bswmds.get(moduleShortName)` returns undefined | `BSWMD map missing module '<X>' (needed by sheet '<Y>'). Provided modules: <list or '<empty>'>`        | `xlsxToEcucBatch-bswmds.test.ts: missing module throws with provided list` |
| Container not in BSWMD | `lookupContainerDef(mod, sheet)` returns null   | `Container '<X>' not found in BSWMD module '<Y>'. Verify the BSWMD declares this container shortName.` | `xlsxToEcucBatch-bswmds.test.ts: container not in BSWMD throws`            |

All three errors fail-fast — the mapper throws on the first invalid row, before any `PatchStep` is emitted. This is a strict improvement over the v1.25.x PATCH behavior where the mapper emitted a `path-not-found` patch and the engine silently soft-filtered it.

Existing engine-side error handling is unchanged: `param-not-found`, `set-param` failures, etc. flow through the existing channels.

## Risks and Mitigations

| Risk                                                                                                       | Likelihood | Mitigation                                                                                                                                                                                                                                                    |
| ---------------------------------------------------------------------------------------------------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `lookupContainerDef` semantics don't match mapper's expectation (e.g., case-insensitive name match needed) | Low        | `lookupContainerDef` is already exercised by `bswmd.test.ts`; mapper's lookup is mechanical. Add an integration test that proves a real demo BSWMD resolves correctly.                                                                                        |
| `lookupContainerDef` doesn't recurse into sub-containers we need                                           | Low        | The function already recurses sub-containers (`bswmd.ts:458` docstring). All 5 sheet kinds are top-level or single-level sub-containers of ECUC-MODULE-DEF; both cases covered.                                                                               |
| Demo-ecu BSWMDs are missing one of the 5 modules                                                           | Low        | `parseDemoBswmds` returns a map; missing module → "BSWMD map missing module '<X>'" error surfaces to user. Demo fixture at `samples/arxml/demo-ecu/bswmd/` declares Com/CanIf/PduR/ComM (and possibly others); verify in pre-flight.                          |
| Real-OEM fixture BSWMD shape differs from demo fixture (different shortName casing, different nesting)     | Medium     | Tested via existing real-OEM integration test; if mismatch surfaces, the mapper's error is fail-fast at construction (better UX than silent path-not-found). Resolution: update demo BSWMD path key to match real-OEM, or add a per-module BSWMD alias table. |
| `xlsxEcucBatchImportHandler.ts` parsing all 5 demo BSWMDs at startup adds latency                          | Low        | BSWMD files are small (~5-15 KB each, 5 files = ~50 KB total). Parsing is fast (<10ms total). User-visible latency: negligible.                                                                                                                               |
| Existing tests assert literal path strings; refactor breaks them                                           | Medium     | The assertion updates in `xlsxToEcucBatch.test.ts` and `xlsxEcucBatchImportHandler.test.ts` are explicit. Net assertion count preserved.                                                                                                                      |
| Backward compat: external callers of `xlsxToEcucBatch` rely on the no-BSWMD signature                      | None       | Function is internal main-process code; one production caller. Updated in same MINOR.                                                                                                                                                                         |
