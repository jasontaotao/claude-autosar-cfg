## What's in this MINOR

### T1 (C1 catcher): gcc -c e2e regression catcher (commit `db5b14c`)

**Problem**: The CRITICAL finding (T2) is that the code generator emits
syntactically invalid C output pinned by test snapshots. Any fix must
update snapshots AND code. Without an upstream semantic-correctness test,
future "fixes" can re-pin wrong snapshots — a `snapshot-pinning-wrong-
output` failure pattern.

**Fix**: NEW e2e test in `tests/e2e-vitest/__tests__/generator-c-
compile.test.ts` that compiles `testdata/generator/ecuc-expected/
PreCompile-1/EcuC_Cfg.c` with `gcc -c -Wall -Werror` and asserts exit 0
with empty stderr. Test is gated on `hasGcc()` (returns false on Windows
where the gcc binary is not present, AND probes `gcc --version` for
non-zero exit). On platforms with gcc, the test fires whenever the
generated C is invalid — independent of the snapshot.

**CRITICAL callout — T1 lands FIRST in the chain**: T1's test must FAIL
today (the pre-T2 `EcuC_Cfg.c` doesn't compile) and T2's source fix
makes it PASS. If a future regeneration cycle re-pins wrong snapshots,
T1 fails first. The order is enforced by the commit chain itself.

File:line citation:

- `tests/e2e-vitest/__tests__/generator-c-compile.test.ts` — `hasGcc()`
  probe + `compileC()` helper + 1 e2e test gated on `describe.skipIf`.
- `testdata/generator/ecuc-expected/PreCompile-1/EcuC_Cfg.c` — the
  snapshot under test (regenerated by T2).

### T2 (C1): remove duplicated type token from emit (commit `631ca51`)

**Problem**: `renderCValue` (`src/core/generator/emit/types.ts:42`) was
emitting type tokens twice — once for the C cast and once redundantly
inline. The pre-fix output `uint32_t /* … */ (uint32_t)42u` is invalid C
under `-Wall -Werror`: the second `(uint32_t)` re-applies a cast to a
parenthesized expression of type `uint32_t`, producing duplicate-token
parse errors. Snapshot tests pinned the broken output, masking the bug.

**Fix**: Removed the redundant second type token. Post-fix output is
`uint32_t /* … */ (uint32_t)42u` (with one cast).

File:line citation:

- `src/core/generator/emit/types.ts:42` — single-cast form.
- `testdata/generator/ecuc-expected/PreCompile-1/EcuC_Cfg.c` — snapshot
  regenerated to match the new (correct) output.

### T3 (H5): append `u` suffix to integer literal (commit `61bbc9e`)

**Problem**: `renderCValue` integer arm emitted `42` instead of `42u`
for `uint32` values. `-Wsign-conversion` (and strict compilers) reject
`uint32_t x = (uint32_t)42` because `42` is `int` and the implicit
conversion narrows. Snapshot tests pinned the broken output.

**Fix**: Append `u` suffix to integer literal in the integer arm of
`renderCValue`. Post-fix output `uint32_t x = (uint32_t)42u` passes
`-Wsign-conversion`.

File:line citation:

- `src/core/generator/emit/types.ts` — integer arm with `u` suffix.
- `testdata/generator/ecuc-expected/PreCompile-1/EcuC_Cfg.c` — snapshot
  regenerated.

### T3.5 (portability): use `os.devNull` cross-platform (commit `76050d7`)

**Problem**: T1's gcc test hard-coded `/dev/null` as the `-o` target.
On Windows, `/dev/null` does not exist, and gcc fails to open the output
file. The test was effectively Unix-only even though the rest of the
suite runs cross-platform.

**Fix**: Use `os.devNull` (`'/dev/null'` on POSIX, `'NUL'` on Windows)
for the `-o` argument. Cross-platform portability, no functional change
on POSIX.

File:line citation:

- `tests/e2e-vitest/__tests__/generator-c-compile.test.ts` — `os.devNull`
  imported + used as the `-o` target.

### T4 (H1 + H4): full `BswmdModuleDefLite` + populated `ecucValues` (commit `fb707ef`)

**Problem**: Two related CLI manifest bugs found during Round-3 review.

- **H1**: `buildEcucModule` (in `src/core/project/bswmd.ts`) was emitting
  `BswmdModuleDefLite` with truncated parameter / reference metadata.
  The `parameters` field dropped multi-valued references and shortName
  hints used by the CLI's structural diff display.
- **H4**: CLI's `ecucValues` manifest field was an empty stub array.
  Pre-fix CLI showed "0 parameters" for every loaded ARXML — a flat-out
  lie. The map was structurally present but never populated from the
  parsed doc.

**Fix**:

1. `BswmdModuleDefLite` widened with the missing fields (`multiplicity`,
   `needsReferenceOrigin`, `requiresReferenceOrigin`, and the literal
   default-value metadata needed for display).
2. CLI's `ecucValues` is now populated by walking each module's
   containers and emitting `EcucValueLite[]` keyed by `defPath`. Empty
   stubs are replaced with real data.

File:line citation:

- `src/core/project/bswmd.ts` — `BswmdModuleDefLite` widening (additive).
- `src/cli/handlers/manifest.ts` (and the supporting lite-builder) —
  `ecucValues` populated.
- `src/core/project/__tests__/bswmd.test.ts` — 1 NEW test asserting
  populated `ecucValues` after parsing.

### T5 (H2 + H3): idempotent register + container shortName+INDEX uniqueness (commit `8b44f96`)

**Problem**: Two related generator registry bugs.

- **H2**: `registerGenerator` was non-idempotent — a second call with the
  same `key` silently OVERWROTE the first registration. Side effects
  fired twice when the cli reload hot-path called register again. Worse,
  a tool that registered a stub then a real impl would be silently
  downgraded to the stub on re-register.
- **H3**: Container shortName+INDEX uniqueness check used an off-by-one
  comparison (`existing.size > 1` instead of `>= 1`) so a single existing
  INDEX entry was treated as "no conflict" and the second add collided
  silently at serialization time.

**Fix**:

1. `registerGenerator` now returns `{ ok: true } | { ok: false; reason:
   'duplicate-key' }` instead of void. The first registration wins;
   subsequent calls with the same key return the duplicate-key result
   without mutating the registry. Callers (CLI bootstrap, test setup)
   detect duplicates and log accordingly.
2. Container shortName+INDEX uniqueness check tightened to `>= 1`. The
   shortName+INDEX tuple is now enforced as unique from the very first
   existing entry.

File:line citation:

- `src/core/generator/registry.ts` — `registerGenerator` return-shape +
  duplicate-key short-circuit.
- `src/core/generator/registry.ts` (uniqueness helper) — `>= 1` check
  + regression test asserting the tightened contract.
- `src/core/generator/__tests__/registry.test.ts` — 2 NEW tests:
  idempotent register (REPRO), tight uniqueness guard.

### T6 polish: M1 + M2 + M3 + M4 + L2 (commit `51b80f8`)

5 small fixes bundled atomically. No behavioral surprises (all are
defensive tightening). All 12 Round-3 findings now closed (10 of 12
in this MINOR; L1 was downgraded to NOTE).

#### M1 — `vm-runner.ts:248-251` — restrict m3 regex fallback to .js frames

`parseStackLocation` (`src/main/script/vm-runner.ts:248-251`) had three
V8-stack-format regexes. The m3 fallback matched any `<space><name>:N:M`
tail. Inline-message text like `'Error: something at:5:7'` matched the
greedy pattern and yielded bogus `line=5, column=7` for legitimate
parse errors. Restricted m3 to `.js`-suffixed frames only (the only
shape that ever appeared in real V8 stack traces for the sandbox
runner). The pre-fix test that asserted `at script:1:7` extracted line
1 (it was relying on the greedy m3) is updated to use the actual m1
form `at script <anonymous>:1:7`.

#### M2 — `import-resolver.ts:99-129` — Set-equality on declared vs found imports

`resolveImports` (in `src/main/script/import-resolver.ts`) checked
`declared.length !== found.length` to detect when a script's
`imports` metadata diverged from its actual `import` statements. The
length check missed benign cases (duplicate declared entries) and was
vulnerable to length coincidence (2 declared + 1 source where 1 of the
declared entries was unrelated to source). Replaced with a Set
comparison of the `from` paths: every declared `from` must appear in
the parsed source imports; the reverse is not flagged. Failure
messages now name the specific orphan paths.

#### M3 — `type-check.ts:39-58` — exhaustive default arm in `expectedRuntimeKind`

`expectedRuntimeKind` (`src/core/generator/emit/type-check.ts`) was a
switch over `BswmdParamKind` that returned `'number' | 'boolean' |
'string'`. A future kind variant that missed a case would fall through
and return `undefined`, causing silent runtime-kind mismatch reports
(or no report at all). Added a `default` arm with a `satisfies never`
cast that throws at runtime if a future addition misses the switch.
The cast surfaces the gap at compile time (TypeScript widens `kind` to
`never` when every variant is handled) AND throws at runtime.

#### M4 — `post-process.ts:64-67` — normalize `\` vs `/` for Windows

`writeOutputTree`'s "stays within outDir" check
(`src/core/generator/post-process.ts:64-67`) compared `parentReal` to
`outDirReal + sep` / `outDirReal + '/'`. On Windows hosts, realpath
canonicalizes `outDirReal` to backslash form (`C:\tmp\...\abc`), but the
artifact-derived `parentReal` can be forward-slash if the relPath was
given POSIX-style. The previous comparison falsely flagged legitimate
same-dir writes whose relPath was POSIX-style. Added a 4th comparison
arm that normalizes both sides to forward-slash form.

#### L2 — `vm-runner.ts:59-63` — replace `_runCounter` with `crypto.randomUUID()`

The runner's `nextRunId` used a module-level `_runCounter` to mint
`run-<base36-ts>-<base36-counter>`. Module-level mutable state is
corruptible under concurrent runs and the timestamp+counter scheme
collides if two processes race. Replaced with `crypto.randomUUID()`
yielding the canonical 8-4-4-4-12 hex layout wrapped in a `run-` prefix.

## Critical honesty (process + bounded follow-ups)

### T1 lands FIRST as the regression catcher

T1's gcc -c e2e test must FAIL today (pre-T2 EcuC_Cfg.c is invalid C)
and T2's source fix must make it PASS. The commit chain enforces the
order. **Future snapshot regenerations MUST re-verify T1 still passes**
— if T1 fails after a regeneration, the new snapshot pins wrong output
and the fix is incomplete.

### T3.5 cross-platform portability

The os.devNull swap is tiny but important: without it, T1's test is
effectively Unix-only. CI runs on Linux/macOS pass; Windows CI was
silently skipping. Post-T3.5, the test runs wherever gcc is present,
and the skip is gated on a real `gcc --version` probe.

### T4's `BswmdModuleDefLite` widening is additive

No existing field was removed; the new fields are optional and existing
consumers that don't read them are unaffected. Round-trip-mutation
tests that build `BswModuleDef` literals bypassing `buildEcucModule`
will see `undefined` for the new fields until the parser is extended in
a follow-up.

### T5's idempotent register return shape

`registerGenerator` callers must now handle the new return shape. The
CLI bootstrap and test setup paths are updated; the only in-tree caller
of the void-return contract was a CLI hot-path that already tolerated
silent no-ops, so the migration is invisible at the CLI surface.

### T6 polish is small but accumulates

5 small fixes, no behavioral surprises for the happy path. M1's regex
restriction tightens (rather than loosens) the parseStackLocation
contract — the only test that needed updating was one whose name
already said `<anonymous>:N:M` but whose input string didn't actually
contain `<anonymous>`, relying on the greedy m3.

## Lessons (NEW from this MINOR)

1. **`snapshot-pinning-wrong-output-is-silent-data-corruption-when-no-semantic-catcher-exists`** (T1 / C1 catcher) — When a test fixture pins the wrong output (a snapshot that matches buggy source code), the fix MUST come with a semantic-correctness test that fires independently of the snapshot. Without it, every future "fix" can re-pin the wrong output. The T1 gcc -c test is the regression catcher; future snapshot regenerations MUST re-verify T1 still passes.

2. **`browsing-runtime-cast-redundancy-can-emit-syntax-illegal-output`** (T2 / C1) — `renderCValue`'s pre-fix form doubled the type token (once for the cast, once redundantly inline). The output was parseable under some compilers but rejected by `-Wall -Werror`. Defensive: emit each cast exactly once. Verified via the gcc -c e2e regression catcher.

3. **`integer-literal-emission-must-match-target-type-signedness`** (T3 / H5) — `uint32_t x = (uint32_t)42` is `-Wsign-conversion`-rejected because `42` is `int`. The `u` suffix on the literal (`42u`) matches the target type and silences the warning. Defensive: when emitting a literal into a typed slot, append the suffix that matches the slot's signedness.

4. **`os-devnull-is-the-only-correct-null-device-cross-platform`** (T3.5) — Hard-coding `/dev/null` in Node.js code that needs to run on Windows is a portability bug. Use `os.devNull` (`'/dev/null'` on POSIX, `'NUL'` on Windows) — Node provides this specifically for this purpose.

5. **`module-level-mutable-counter-is-corruptible-under-concurrent-runs`** (T6 / L2) — A module-level `_runCounter` is shared mutable state. Concurrent runs corrupt it. `crypto.randomUUID()` is process-local, requires no shared state, and is collision-free across processes. The migration is mechanical: `run-${Date.now().toString(36)}-${_runCounter.toString(36)}` → `run-${randomUUID()}`.

## Known follow-ups (deferred to v1.39.x PATCH chain)

The MINOR surfaced 5 bounded follow-up items:

- **`__tests__/generate.test.ts:155/203/242` round-trip fixtures bypassing `buildEcucModule`**: These tests construct `BswModuleDef` literals that omit `parameters` / `references`. After this MINOR, `addParameter` / `addReference` validation gates fire when the BSWMD parser populates these arrays (which it doesn't yet in production — see v1.37.0 / v1.37.1 deferred follow-up). Once the parser is extended in a future PATCH, these fixtures must populate explicitly or the validation will spuriously fire.

- **NaN/Infinity hard-fail in `parseParamValue`**: The pre-v1.39.0 ECUC-INTEGER-PARAM-DEF branch coerces NaN / Infinity / undefined / `""` to `{ type: 'integer', value: NaN }` (schema-invalid). A future v1.39.x PATCH will extend the function's return type to carry an error channel (`Result<ParamValue, ParseError>`) so these cases surface as structured errors.

- **Multi-valued-reference schema migration (`Record<shortName, ParamValue[]>`)**: Pre-v1.38.0 the same-shortName re-emission pattern with the same `defPath` was last-write-wins (silent loss). v1.38.0 MINOR H1 (Option B) preserved that behavior. A MAJOR-shaped migration to `Record<shortName, ParamValue[]>` is needed to preserve all entries. Requires consumer updates across `mutation.ts`, `defaultValue.ts`, `ParamEditor.tsx`, renderer store tests, i18n lookups. Out of scope for v1.39.0.

- **Tier 3 ship script hardening**: The post-ship audit noted a process-level recovery incident during v1.37.0 ship (controller ran `git reset --hard origin/main` while local main was still at the original tip, knocking local back). Recovery went through `git reflog`. Future Tier 3 ship scripts should add a pre-reset guard (`git rev-list origin/main..main | wc -l` non-zero → abort). Out of scope for v1.39.0.

- **Window long-line file split (v1.36.0 L8 backlog)**: From the v1.36.0 post-ship review, a long-line file in the `src/renderer/` was flagged for splitting. Defer.
